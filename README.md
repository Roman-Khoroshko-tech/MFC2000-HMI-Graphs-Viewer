# MFC2000 HMI Graphs Viewer

**Версія 2.1.** Вебзастосунок для перегляду CSV-архівів HMI перетворювача частоти MFC2000. Будує часові графіки частоти, струмів, напруг і температур та допомагає знаходити потрібні моменти в записі.

Програма працює локально у браузері або зі статичного сайту. Сервер для обробки CSV не потрібен; вибраний файл не надсилається в мережу.

## Можливості

- Запуск одразу в робочому вікні із сімома порожніми графіками стандартних сигналів HMI.
- Відкриття CSV кнопкою в бічній панелі або перетягуванням файлу у вікно.
- Побудова графіків за фактичними числовими колонками відкритого файлу.
- Спільна шкала часу, масштабування колесом миші, прокрутка перетягуванням та огляд усього запису.
- Вибір діапазону дат і часу та відображення значень найближчого запису під курсором.
- Незалежний автомасштаб Y або власні межі «Мін.» / «Макс.» для кожного графіка; кнопки Y+ / Y−.
- Відображення розривів у записі без з’єднання лінією.
- Українська, польська та англійська мови через кнопку UK / PL / EN.
- Світла й темна теми, адаптивне компонування.
- Кнопка **RK ↗** для переходу на [головний портал автора](https://roman-khoroshko-tech.github.io/).

Дата й час зберігаються як у файлі HMI, без перерахунку часового поясу. Поки файл не відкритий, графіки порожні, а керування часовим діапазоном і масштабом неактивне.

## Локальний запуск

1. Завантажте репозиторій або окремий файл `MFC2000-HMI-Graphs-Viewer.html`.
2. Відкрийте `index.html` або `MFC2000-HMI-Graphs-Viewer.html` у настільному Chrome чи Edge.
3. Натисніть **«Відкрити CSV»** в бічній панелі або перетягніть CSV у вікно.
4. Виберіть потрібні сигнали та часовий діапазон.

Обидва HTML-файли в корені містять ту саму автономну програму. Встановлення, Node.js, сервер та інтернет для її локальної роботи не потрібні. Перехід на портал через RK потребує інтернету.

Після закриття або оновлення сторінки CSV потрібно відкрити повторно. Мова й тема зберігаються в `localStorage`, якщо браузер дозволяє його використання; вміст CSV там не зберігається.

## Керування графіками

| Дія | Результат |
| --- | --- |
| Колесо над графіком або верхні + / − | Масштаб часу |
| Перетягування графіка | Прокрутка часу |
| Перетягування виділення або його країв на смузі огляду | Зміна часового діапазону |
| Поля «Від» / «До» та «Показати» | Перехід до заданих дат |
| «Весь період», подвійний клік або Home на графіку | Скидання масштабу часу |
| Зняти «Автомасштаб Y», ввести межі та натиснути «Застосувати» | Ручний вертикальний масштаб |
| Y+ / Y− | Зміна вертикального масштабу |
| ← / → на графіку | Прокрутка часу з клавіатури |

Зміна часового діапазону, мови чи теми зберігає ручні вертикальні межі. Новий CSV створює графіки заново з увімкненим автомасштабом Y.

## Формат CSV

Очікується текстовий файл UTF-8 з рядком заголовків, часовою колонкою `Timestamp` та числовими сигналами. Підтримуються роздільники кома, крапка з комою й табуляція, а також поля в подвійних лапках.

Приклад із синтетичними даними:

```csv
Timestamp,"Frequency [Hz](float)","Motor Curr [A](float)"
06/09/2026 - 00:30:30,40.0,12.5
06/09/2026 - 00:30:35,45.0,15.2
```

Основний формат часу — `dd/MM/yyyy - HH:mm:ss`; також підтримується `yyyy-MM-dd HH:mm:ss`. Десяткова крапка підтримується без додаткових налаштувань. Для десяткової коми використовуйте крапку з комою як роздільник або належно екрановані поля CSV.

Неправильні дати й рядки з іншою кількістю колонок пропускаються з повідомленням. Порожні чи нечислові значення не замінюються нулями. Неупорядковані записи сортуються за часом.

## Технології

- HTML5 та CSS зі світлою й темною темами.
- Звичайний JavaScript без фреймворків і сторонніх бібліотек.
- Canvas 2D для графіків та Web Worker для читання CSV й підготовки даних.
- Браузерні File API та `localStorage` для налаштувань мови й теми.
- Node.js і його стандартні модулі для збирання автономного HTML.

У проєкту немає залежностей npm або CDN. `package.json` містить лише метадані й команди збирання та перевірки. Значення `private: true` запобігає випадковій публікації пакета в npm і не визначає видимість репозиторію GitHub.

## Структура проєкту

```text
.
├── index.html                         # готова головна сторінка / GitHub Pages
├── MFC2000-HMI-Graphs-Viewer.html      # та сама програма для окремого завантаження
├── src/
│   ├── index.html                     # вихідна сторінка з локальними ресурсами
│   ├── assets/
│   │   ├── app.js                     # керування графіками й інтерфейсом
│   │   ├── app.css                    # стилі застосунку
│   │   ├── data-utils.js              # пошук, діапазони та відбір точок
│   │   ├── i18n.js                    # переклади UK / PL / EN
│   │   └── worker.js                  # читання та підготовка CSV
│   └── ui/                            # базові локальні стилі й тема
├── build.cjs                          # збирання та перевірка готових HTML
├── package.json
├── .gitignore
├── .gitattributes
└── .nojekyll                          # статичне розміщення без обробки Jekyll
```

Робочі CSV, ключі доступу, локальні налаштування та результати перевірок до репозиторію не входять. Обидва готові HTML-файли залишені навмисно: один є головною сторінкою, інший зручний для завантаження під повною назвою.

## Збирання та перевірка

Для розробки потрібен Node.js. Встановлювати додаткові пакети не потрібно.

```sh
node build.cjs
node build.cjs --check
```

Альтернативні команди: `npm run build` і `npm run check`. Перша команда оновлює обидва готові HTML-файли. Перевірка читає локальні ресурси, перевіряє синтаксис JavaScript і відповідність готових файлів вихідному коду без запису змін. Вона не замінює перевірку інтерфейсу у браузері.

Редагуйте `src/`, після змін запускайте збирання. Для перегляду вихідної версії можна також відкрити `src/index.html` безпосередньо в браузері.

## GitHub Pages

У корені вже є готовий `index.html` з усіма потрібними стилями та скриптами. Збирання на сервері й GitHub Actions для запуску сайту не потрібні.

Після завантаження підготовлених файлів у GitHub у **Settings → Pages** можна вибрати **Deploy from a branch**, гілку **main** та каталог **/ (root)**. Файл `.nojekyll` вимикає обробку Jekyll. Вихідна сторінка використовує відносні шляхи й також працює у вкладеному каталозі.

Ці файли лише готують проєкт до розміщення; налаштування GitHub Pages виконується окремо.

## Межі перевірки

Роботу перевірено у Chromium: порожнє робоче вікно, завантаження CSV, масштабування, мови, теми та компонування за різної ширини екрана. Перевірки використовують синтетичні дані. Safari, Firefox і фізичні сенсорні пристрої окремо не перевірені.
